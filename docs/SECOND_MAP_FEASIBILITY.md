# Feasibility второй полноразмерной карты

## Вывод

На уровне документированного RScript 4.10f полноценная вторая нативная карта в
одном сохранении **не подтверждена**. Имеющийся API позволяет читать и менять
объекты текущей галактики, но не создаёт второй объект Galaxy и не переключает
активный контекст. При этом подтверждён поддерживаемый RScript путь к 32-битной
DLL; для него собран минимальный безопасный адаптер ABI 4.

## Что подтверждено

- `GalaxyStars`, `GalaxyStar`, `GalaxySectors` перечисляют текущую карту.
- `GalaxyPtr()` возвращает указатель на **текущий** объект Galaxy.
- Setter для `GalaxyPtr` в списке функций отсутствует.
- `StarOwner` и `StarCustomFaction` меняют владельца существующей системы.
- `HoleCreate2` связывает две существующие системы текущей галактики.
- `TransferShip` переносит корабль/станцию к существующей системе, планете или
  станции; это не сериализация/переключение карт.
- `SectorVisible` открывает существующий сектор, но не создаёт новую карту.

## Чего нет в документированном API

- `CreateGalaxy` / `NewGalaxy` / `SwitchGalaxy` или эквивалента;
- создания звёзд и секторов во время партии;
- второго независимого набора нативных NPC, экономики и фронтов;
- сериализации двух Galaxy в одном `.sav`;
- UI-переключателя двух карт;
- атомарного переноса игрока между двумя Galaxy.

## Оценка вариантов

| Вариант | Пригодность | Статус |
|---|---|---|
| скрытый сектор на текущей карте | годится только для spike | не выполняет 1.0 |
| агрегированная вторая карта в массивах RScript | может доказать seed и фоновые тики | визуально не полноценная карта |
| замена/пересборка текущей карты | высокий риск потери ссылок и save | API не найден |
| расширение `Rangers.exe` / движка | потенциально соответствует цели | требует отдельного reverse-engineering проекта |
| отдельное сохранение | технически проще | нарушает требование одного save |

## CE-SPIKE-MAP

Безопасный первый spike реализован в `tools/second_map_spike.py`: он хранит
отдельные seed и состояния рукавов, проверяет масштаб ±10%, выполняет три
перехода, расходует ячейки ровно один раз и восстанавливает незавершённую
транзакцию после сбоя. Это исполняемая модель контракта, а не финальная нативная
карта.

## CE Second Map Adapter ABI 6

Собран PE32/i386 `CESecondMapAdapter.dll`. Отдельный x86 host и реальная новая
игра подтвердили загрузку ABI 3, `cdecl`, передачу ненулевого `GalaxyPtr()` и
ограниченный read-only fingerprint через `ReadProcessMemory`.
ABI 4 добавляет одноразовый 256-байтный read-only layout sample: только четыре
хеша и маски zero/readable-pointer без сырых значений и адресов. Он прошёл x86
host и три независимых игровых процесса. Блок 128–191 дал одинаковый хеш во всех
трёх новых играх; детальные offsets и ограничения вывода записаны в
`GALAXY_LAYOUT_ABI4_RESULTS.md`. Адаптер не патчит процесс и сообщает
`native multi-galaxy = false`. Контракт описан в `SECOND_MAP_ADAPTER_ABI.md`.

ABI 5 подтвердил rolling read-only наблюдение `CurTurn 300 -> 301` в одном
процессе. Same-turn sample после load не получен: сохранённый RScript не вызывает
ни `Turn`, ни `Init` до следующего игрового дня. Результат зафиксирован в
`GALAXY_LAYOUT_ABI5_RESULTS.md`; stale PID теперь отклоняется анализатором.

Следующий gate больше не зависит от RScript callback: отдельный PE32
`ce_galaxy_attach.exe` открывает `Rangers.exe` только на query/read, сканирует
подтверждённые 256-байтные признаки и не публикует адреса или сырые данные.
Синтетический end-to-end самотест пройден. На загруженном save строгий и
устойчивый профили оба нашли ровно один одинаковый кандидат, закрыв same-turn
read-only discovery без RScript callback. Контракт описан в
`GALAXY_READONLY_ATTACH.md`.

ABI 6 добавляет pointer-normalized hashes в in-process adapter и внешний attach
scanner. Offline build/host gate и реальный save/load gate пройдены. В цикле
`CurTurn 301 -> 302 -> save -> restart -> load 302` сырые хеши всех блоков
между процессами различались, но pointer-normalized блоки 0 и 3 совпали; zero и
pointer-class masks сохранились. Результат записан в
`GALAXY_LAYOUT_ABI6_RESULTS.md`.

## Решение для планирования

1. CE-P00 и War Apart snapshot можно делать обычным RScript-модом.
2. Производство 40 корпусов и 24 баз отложить до выбора архитектуры карты.
3. Выполнить безвредный in-game smoke импорта DLL, затем bind `GalaxyPtr()`.
4. Исследовать формат `.sav`, layout `Galaxy` и UI только для Steam build
   `20648864`, не перенося предположения между версиями.
5. Native switch и расширение save реализовывать отдельными capability gates.

Статус: **OFFLINE SPIKE PASSED / ABI 5 TURN SAMPLE PASSED / SAME-TURN READ-ONLY ATTACH PASSED / ABI 6 NORMALIZED SAVE-LOAD PASSED / NATIVE SWITCH BLOCKED**.
