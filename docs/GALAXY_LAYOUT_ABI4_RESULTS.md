# Galaxy layout ABI 4 — read-only результаты

## Условия

- игра: Steam build `20648864`, `Rangers.exe 2.1.2500.0`, x86;
- три новые игры в трёх отдельных процессах;
- в каждом процессе RScript передал текущий `GalaxyPtr()`;
- адаптер один раз скопировал первые 256 байт через `ReadProcessMemory` после
  проверки всего диапазона `VirtualQuery`;
- JSONL не содержит сырых байтов или адресов;
- во всех трёх запусках отсутствовали окна ошибок и подозрительные новые строки
  игровых логов.

## Результат сравнения

| Блок | Диапазон | Уникальных FNV-1a | Вывод |
|---|---:|---:|---|
| 0 | 0–63 | 3 | состояние зависит от процесса/новой игры |
| 1 | 64–127 | 3 | состояние зависит от процесса/новой игры |
| 2 | 128–191 | 1 | первый стабильный 64-байтный инвариант |
| 3 | 192–255 | 3 | состояние зависит от процесса/новой игры |

Стабильный хеш блока 2 во всех трёх выборках: `1382773990` (`0x526C38A6`).

Всегда нулевыми были dword по offsets:

```text
40, 64, 76, 120, 124, 128, 136, 140, 144, 148, 152, 180,
184, 188, 200, 204, 208, 212, 220, 228, 236, 244, 248, 252
```

Всегда классифицировались как выровненные адреса читаемых committed-регионов:

```text
0, 44, 48, 52, 56, 60, 112, 116, 192, 196
```

Offset `92` классифицировался как читаемый адрес только в одной из трёх игр.

## Что эти данные не доказывают

- Маска readable-pointer может содержать случайные целые числа, попавшие в
  отображённый читаемый регион; это не доказательство типа поля.
- Одинаковый хеш блока 2 не доказывает, что блок константный после хода,
  save/load или для других настроек галактики.
- Никакая длина объекта, таблица полей, ownership или функция-конструктор пока
  не установлены.
- Данные не разрешают запись в Galaxy, переключение указателя или расширение save.

## Следующий gate

Снять отдельные read-only образцы одной и той же партии до сохранения, после
изменения игрового дня и после save/load. Только затем можно сузить кандидаты на
стабильные служебные поля. Capability native multi-galaxy остаётся выключенной.
