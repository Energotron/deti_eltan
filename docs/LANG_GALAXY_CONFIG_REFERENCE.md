# Lang.dat: структура разделов, влияющих на генерацию галактики

Всё ниже получено расшифровкой **реального** `CFG/Rus/Lang.dat` установленной игры
через `references/tools/BlockParEditor_1.9/BlockParEditor.exe --cli --convert`
(2.4 МБ текста, кодировка CP1251), а не по документации и не по аналогии.
Формат разделов проверялся ещё и по рабочему стороннему моду
`Mods/Reflection/RefABitMoreStars`, который меняет число систем.

## Как расшифровать самому

```bash
BlockParEditor.exe --cli --convert <путь к Lang.dat>
```

Файл рядом с исходным, `.txt`, в CP1251. Работает и на ванильном `Lang.dat`,
и на собранном моде — то есть результат сборки можно проверять, а не угадывать.

## Кодировка (важно)

`Lang.dat` — CP1251. Исходники мода в репозитории лежат в UTF-8, поэтому
`tools/build-game-smoke.ps1` обязан перекодировать их при сборке. Раньше
`CE_MapSmoke.Lang.txt` копировался сырыми байтами (`ReadAllBytes`) — UTF-8
уезжал в движок как есть, и все кириллические имена приходили мохнатым
мусором вида «РРССРРЁ». Исправлено: файл читается как UTF-8 и
перекодируется в CP1251, как это уже делалось для `CE_InterarmTransit.Lang.txt`.

## Constellations — секторы и размеры галактики

```
Constellations ^{
    GalaxyCountStars=146
    GalaxySizeX=198
    GalaxySizeY=141
    Name ^{
        1=Гурт
        ...
        20=Дицея
    }
}
```

- В ванили ровно **20** записей `Name`, индексы с 1.
- `GalaxyCountStars` — число систем, по умолчанию 73. Это то же поле, которое
  движок читает из `[galaxy+0x160]` (подтверждено дизассемблированием
  `TGalaxy.GenerateStars`: при значении <= 0 цикл создания пропускается).
- `GalaxySizeX`/`GalaxySizeY` — размер галакарты, по умолчанию 140x100.
  Применяется только при генерации НОВОЙ галактики и автоматически
  растягивает границы существующих секторов.

**Открытый вопрос:** добавление записей `Name` с индексами 21+ количество
секторов НЕ увеличивает — движок по-прежнему строит 20, просто более крупных.
Значит число секторов задаётся не длиной этого списка. Отдельного параметра в
документации нет; искать так же, как искали `GalaxyCountStars` — дизассемблируя
генератор и глядя, откуда берётся число секторов.

## Star — имена систем

```
Star ^{
    00=Тарон,Star.Normal
    01=Пхедок,Star.Normal
    02=Солнце,Star.Small
    ...
    72=<последняя ванильная>
}
```

- Записи лежат в `Star` **напрямую**, без вложенного блока `Name`.
- Индексы **с нуля**, в ванили двузначные с ведущим нулём (`00`..`72` = 73 имени).
- У каждой записи обязателен второй элемент — тип звезды: `Star.Normal` или
  `Star.Small`.
- Мод добавляет имена, продолжая нумерацию: для `GalaxyCountStars=N` нужны
  индексы `0..N-1` без пропусков.

Типичная ошибка (совершена в этом проекте): завернуть имена в
`Star ^{ Name ^{ 74=… } }` по аналогии с секторами и начать с 74. Движок такой
блок не читает вообще.

## PlanetName — имена планет

Раздел разбит на **подсекции по расам**, а не плоский список:

```
PlanetName ^{
    Fei ^{
        01=Умий
        02=Эйпентак
        ...
    }
    ...
}
```

679 строк в ванили. Имена планет — одиночные выдуманные слова, сильно разной
длины, изредка через дефис.

## RuinName — имена станций и баз

Тоже разбит на **подсекции по типам** объектов:

```
RuinName ^{
    BK ^{
        1=Эконом
        10=Высокой активности
        11=Толстяк
        ...
    }
    ...
}
```

350 строк в ванили. Индексы без ведущих нулей. Имена смешанные: одиночные
слова («Толстяк», «Магнат») и словосочетания («Красный барон»).

## Как это соотносится с планами мода

Пулы имён из конфига раздаются движком случайно по всей галактике — привязать
«наши» имена только к дальней половине через конфиг нельзя. Для этого в проекте
уже есть работающий механизм переименования в живой памяти
(`tools/native/ce_sector_name_helper.c` плюс пулы `g_ce_second_planet_names` и
`g_ce_second_station_names` в адаптере). Правильный порядок: конфигом добиться
нужного числа систем и секторов, затем переименовать дальнюю половину.
