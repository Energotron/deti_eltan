# Каталог присланных инструментов и материалов по моддингу

Составлено после того, как пользователь скинул пачку архивов с рабочего стола
и ссылок на инструменты/репозитории с просьбой "изучи и пойми, для каких
задач что пригодится, сохрани себе". Это не про решение одной конкретной
задачи (второй галактики) — это общий каталог "что есть и когда доставать".

Все ZIP лежат на `C:\Users\mrsam\Desktop\`. Ничего из них не скопировано в
репозиторий (кроме уже ранее вендоренного `references/`) — при необходимости
распаковывать заново из Desktop.

## Компиляция скриптов и конфигов (уже используется в сборке)

- **`RScript_4.10f.zip`** — компилятор `.rson` → `.scr` (Turn/Global-код).
  Именно этот `RScript.exe` уже используется в `tools/build-game-smoke.ps1`.
  Внутри также лежит папка `BlockPar/` с отдельным `BlockPar.exe`/`DataIO.dll`
  — судя по всему, встроенная копия более общего BlockPar-редактора,
  используемая RScript'ом как зависимость.
- **`BlockParEditor_1.9.zip`** — компилятор `Main.txt` → `Main.dat` (UI-панели,
  `OnKey`, чит-коды). Тоже уже используется в сборке.
- **`rscript_noeditor.zip`** — **настоящий Pascal-исходник** этих двух
  инструментов (`EC/EC_Expression.pas` — 6047 строк, компилятор
  выражений/операторов; `EC/EC_BlockPar.pas` — 1587 строк, парсер
  BlockPar-дерева; `Forms/Form_Build.pas` и др. — GUI). Полезно, если
  когда-нибудь понадобится: (а) понять грамматику RScript на уровне токенов
  дословно, а не по документации; (б) написать свой тул, который
  программно читает/пишет `Main.txt`/`.rson` через тот же формат BlockPar-
  дерева (`Par_Add`, `Block_Add`, `El_Get` и т.д. — есть готовый Pascal API).
  Важная проверка, которую это дало: слово `OnKey` в этом исходнике **не
  встречается вообще** — значит, `OnKey ~{...}` не компилируется этим
  инструментом в байт-код, а хранится как обычный текст внутри
  BlockPar-дерева и разбирается уже самим Rangers.exe в рантайме (закрытый
  код, которого нет ни в одном присланном материале). Отсюда же вывод: то,
  что первая подходящая по условию численная ветка `OnKey` гасит остальные
  (найдено эмпирически в этом проекте на живых тестах) — это не
  задокументированное нигде поведение, открытое этим проектом самостоятельно.

## Редактирование ресурсов/UI

- **`ResEditor_1.3.2_updated.zip`** — три экзешника (`_hai128/256/384`,
  видимо разные варианты хэша/алгоритма под ресурсы) + `Sound.dll`/`StarGL.dll`.
  Судя по форумному мануалу (см. ниже), инструмент показывает, за какую
  визуальную форму отвечает какой элемент `Main.dat` (пример из мануала:
  "в FormShip2 много элементов из Ml.Ship"). Доставать, когда нужно
  разобраться, какой Main.dat-элемент рисует конкретный кусок интерфейса,
  или отредактировать сами графические ресурсы/иконки.
- **`WImage_2.1.zip`** — `WImage.exe` + `OKGF.dll` (свой формат графики) +
  примеры `Script/ItemsBuild.txt` и `Script/Planet.txt`. Инструмент для
  сборки/редактирования графических ресурсов игры (иконки предметов,
  спрайты планет и т.п.).

## Реверс-инжиниринг скомпилированных скриптов

- **`HowToReverse.zip`** — уже использован в этом сеансе: `scr_dump/dump.py`
  реально декомпилирует `.scr` обратно в читаемый RScript (пропатчено под
  версию 8 нашего компилятора, подтверждённо работает). Внутри же —
  реальные декомпилированные ванильные скрипты кораблей ИИ:
  `dumps/MS_Keller.dump`, `MS_Begin.dump`, `MS_Blazer.dump`, `MS_PB.dump`,
  `MS_SB1/2.dump`, `MS_Terron.dump`, `PC_part0..6.dump`, `PC_destroyer.dump`,
  `PC_final.dump`, `PC_fem_rangers.dump` — готовые примеры, как устроены
  скрипты диалогов/поведения кораблей в ванили. Полезно как справочник по
  ЛЮБОЙ будущей задаче, трогающей ИИ кораблей, диалоги или квестовые
  сценарии — не только для декомпиляции, но и как готовые примеры паттернов.
  Ограничение: покрывает только `.rson`/`.scr` (Turn/Global-код), не
  `Main.txt`/`OnKey` (тот компилируется в отдельный `Main.dat`).

## Справочник и примеры скриптового API

- **`Modding_manual_snkgames_attachments.zip`**:
  - `example_scripts/aScriptFun.pas` — Pascal-исходник экспортируемых
    скриптовых функций. У нас уже есть более полная и свежая копия
    (`references/Universe-Original-Mods-Source/aScriptFun_.pas`,
    идентична `references/Space-Rangers-Mods-Sources/script-functions/
    aScriptFun.pas` — оба уже в репо, 15347 строк против 15169 в этом
    архиве) — эту копию обновлять не нужно.
  - `artifact/artifact.txt` — полный рабочий пример кастомного артефакта
    (Dominator-артефакт "Стволовик") с реальным `OnActCode`. Хороший шаблон,
    если понадобится писать свой кастомный артефакт.
  - `example_scripts/Std Functions` — примеры кастомных `SF_*`
    вспомогательных функций (напр. `SF_Min`) — шаблон, если понадобится
    писать свою стандартную функцию для скриптов.
  - `example_scripts/PC_part0.svr`, `PC_part1.svr`, `test_quest.svr` —
    настоящие ПРОЕКТЫ скриптов (не декомпилированный дамп, а исходный
    `.svr`, открывается визуально прямо в RScript.exe).
  - `functions_all/functions_all.txt` — ещё один, более сжатый вариант
    справочника функций (отличается от `Script functions list.txt`).
  - `Lang.dat-Artefacts.xlsx` — таблица Lang.dat-записей по артефактам.
  - `MyMod/` — полный минимальный рабочий скелет мода (CFG/Main.dat,
    CFG/CacheData.dat, CFG/Rus/Lang.dat, Data/Script/my_script.scr) —
    удобный референс "как выглядит минимально рабочий мод целиком".

## Готовый корпус: ваниль + чужие моды в текстовом виде

- **`DAT (vanilla + mods) converted to txt 14.09.22.zip`** (5.6 МБ) —
  ПОЛНОСТЬЮ декомпилированный ванильный `CFG/Main.txt` (37700+ строк),
  `CFG/CacheData.txt`, `CFG/Rus|Eng/Lang.txt`, ПЛЮС папка
  `Mods/AnotherMods/...` с уже декомпилированными Main.txt/Lang.txt/
  CacheData.txt чужих модов (AMod_CammonPanel, AMod_DefStation,
  AMod_Invaders и другие). Подтверждено: ванильный `Main.txt` НЕ использует
  `OnKey ~{...}` вообще ни разу — это не стандартный ванильный паттерн.
  Ценность: можно grep'ать этот корпус на любой вопрос "а как ваниль/другой
  мод делает X" вместо гадания.

## Подсветка синтаксиса в редакторах

- **`Dab's Code Syntax for Notepad++.zip`** / **`Sublime_Dab_Syntax.zip`** —
  файлы подсветки синтаксиса RScript-подобного кода для Notepad++/Sublime.
  Пригодится для удобства редактирования `.rson`/`Main.txt` глазами; сами
  файлы синтаксиса заодно перечисляют полный список распознаваемых
  ключевых слов/функций — можно свериться как альтернативный источник.

## Инструменты для другой игры (SR2 classic, не HD) — офсеты не переносятся

- **`TrainerRCC_1.3.1.zip`** — трейнер/редактор объектов для классических
  Космических Рейнджеров 2 (НЕ HD). Адреса памяти к нашему Rangers.exe не

  перекликается с нашими собственными находками про нестабильность смены
  типа объекта на лету.

## Итог по актуальной задаче (краш `LoadFromStream` / зависание пустой галактики)

Ни один из материалов не описывает нативное устройство `TGalaxy`,
`SaveToStream`/`LoadFromStream` или механику мультигалактики — все они про
слой RScript/BlockPar-моддинга и готовые ассеты/каталоги модов. Это
ожидаемо: наш собственный дизассемблер (`tools/disasm_rangers.py`) и
`docs/TGALAXY_LOADFROMSTREAM_FORMAT.md` — единственный источник знаний об
этом слое, и решать краш придётся тем же путём.
