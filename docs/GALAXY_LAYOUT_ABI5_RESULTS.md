# Galaxy layout ABI 5 — turn/save/load gate

## Цель

Проверить первые 256 байт одного объекта Galaxy в трёх точках:

1. `before` — карта новой игры;
2. `after` — та же партия после одного игрового дня;
3. `reload` — сохранённый `after` после загрузки в новом процессе без хода.

Все чтения ограничены `VirtualQuery` + `ReadProcessMemory`; сырые байты и адреса
не сохраняются, запись в процесс отсутствует.

## Подтверждённый результат before/after

- процесс: PID `16584`;
- `before`: `CurTurn=300`, sequence `301`;
- `after`: `CurTurn=301`, sequence `302`;
- все четыре 64-байтных FNV-1a хеша изменились после хода;
- zero-mask сохранилась: `0D58404000000400`;
- readable-pointer mask сохранилась: `00070001F000F801`.

Таким образом, rolling latest sampler корректно различает игровые ходы в одном
процессе и не требует неограниченного JSONL. Во время генерации новой игры
RScript последовательно увидел `CurTurn=0..300`, поэтому фиксированный лимит
наблюдений был отвергнут в пользу одного перезаписываемого `latest.json`.

## Подтверждённый блокер reload

Свежий save был создан уже со smoke-скриптом ABI 5. После загрузки и открытия
карты в новом PID `19640`:

- `galaxy-layout-latest.json` остался от PID `16584`, `CurTurn=301`;
- `adapter-smoke.json` и fingerprint не обновились;
- добавленный для проверки `Code.Type=Init` тоже не вызвал DLL;
- карта открылась, видимых окон ошибки не было;
- игровой лог записал `Exception EAbort with message Err` при загрузке; связь этой
  строки с модулем не доказана, поэтому она остаётся подозрительной, а не
  объявляется причиной.

Вывод: сохранённый RScript не предоставляет подтверждённый same-turn callback
после load. `Turn` сработает только при следующем игровом дне, а `Init` не является
load-hook. Поэтому честное сравнение `after` и `reload` одного `CurTurn` через
текущий RScript-мост заблокировано.

## Защита инструмента

Команда `capture` поддерживает `--expected-process-id` и `--expected-turn` и
отклоняет устаревший `latest.json`. Неудачная reload-точка больше не может быть
принята за новый процесс.

## Следующий gate

Создан отдельный строго read-only attach scanner, который ищет кандидатов по
пересечению подтверждённых zero/readable-pointer масок без DLL injection. На
same-turn загрузке строгий и устойчивый профили нашли ровно один одинаковый
кандидат, хотя RScript latest остался устаревшим. Контракт и доказательства
описаны в `GALAXY_READONLY_ATTACH.md`.

Следующий gate — автоматически архивировать обезличенный reload fingerprint и
сравнить его с `after`. По-прежнему запрещены process injection, запись в Galaxy,
native switch и расширение save. `CEAdapterSupportsNativeMultiGalaxy()` остаётся
`0`.
