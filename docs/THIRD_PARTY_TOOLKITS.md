# Что лежит в присланных архивах и чем это полезно

Пять архивов, распакованы в `references/` и не коммитятся (см. `.gitignore`).
Ниже только то, что реально применимо к «Детям Эльтан», с указанием, какие
наши прежние выводы это подтверждает или отменяет.

## ranger-tools — самое ценное

### `game-objects/*.h` — карты структур движка

Готовые раскладки полей: `TGalaxy.h`, `TConstellation.h`, `TStar.h`,
`TPlanet.h`, `TShip.h`, `TPlayer.h`, `THole.h`, `TItem.h`, `TScript.h`,
`VMT.h`. Это то, что проект добывал дизассемблером по одному полю.

`TGalaxy` подтверждает и уточняет наши смещения:

| Смещение | Что это |
|---|---|
| `+0x24` | `player_index` — номер игрока в списке рейнджеров |
| `+0x28` | `TList* stars` — список звёзд (мы звали его «системы») |
| `+0x2C` | `TList* holes` |
| `+0x38` | `TList* planets` |
| `+0x3C` | `TList* rangers` |
| `+0x4C` | `turn` — текущий ход |
| `+0x160` | **число секторов** |
| `+0x164` | `TList* constellations` — список секторов |
| `+0x1CC` | CRC |
| `+0x1D0` | байт, за ним `_1D1` (тот самый флаг «не освобождать») |

Плюс расписаны флаги читов и весь блок тонких настроек партии
(`AA_*`) — агрессия клисан, множители дропа, стартовый опыт и прочее.

### `rangers/sav.py` — формат сохранения

~1500 строк, конвертация сейв <-> JSON в обе стороны. Определение галактики:

```python
cons=List(TConstellation, UInt16)
stars=List(TStar, UInt16)
planets=List(ID, UInt16)
```

Секторы — список с 16-битной длиной, **никакого лимита в 20 в формате нет**.
Готовый пример правки: `modding-tools/sav/patch_galaxy_big/run.py` создаёт
новые секторы, системы и планеты прямо в сейве (`NEW_CONS = 50`).

Отменяет прежнее возражение «править .sav дорого, надо реверсить формат».

### `modding-tools/` — конвертеры

`.dat` <-> JSON/txt (с подписью и проверкой подписи), `.gi`/`.hai` <-> PNG,
`.pkg` <-> папка, `.qm` <-> JSON, `.scr` <-> JSON, компиляция скриптов.
Шире того, что было в проекте.

### `guides/`

`HowToReverse`, `Про датники.txt`, `Типы элементов в интерфейсе.txt`,
шаблоны 010 Editor для графических форматов.

## Space-Rangers-Mods-Sources — как писать нативные моды

### `den/SR_DLL.cpp`

Чужая нативная DLL для этой же игры. По сути набор доступа к памяти,
выставленный в скрипт: `GetDword`/`SetDword`, `GetFloat`, `GetByte`,
`AllocateMemory`/`FreeMemory`/`ReAllocateMemory`, `CopyMem`, и конвертеры
строк `CStr_to_WStr` / `WStr_to_CStr`, которые принимают И возвращают
указатели на строки.

### Типы в объявлении `ScriptLibs`

Из `script-functions/Script functions list.txt`:

```
RoundTo=float,RoundTo,float,float,int
IsShiftCtrlPressed=int,IsShiftCtrlPressed
DeclareBonusArray=void,DeclareBonusArray,int
```

Первым идёт тип возврата. Поддерживаются `int`, `float`, `str`, `void`.
Для аргументов дополнительно доступны:

- `ref` — передаёт не значение переменной, а **указатель на неё**;
- `code` — передаёт указатель на текущий исполняемый объект скриптового
  кода, через который можно достать и менять все переменные скрипта.

**Это отменяет вывод, сделанный в этом проекте раньше**, будто перенос
предметов невозможен из-за того, что имена вещей нельзя вернуть из нативного
кода в скрипт. Можно: объявить возврат `str`, либо писать в переменную через
`ref`. Целочисленный стеш был ограничением нашей реализации, а не движка.

Также есть `ImportAll('LibName')` и объявление
`ScriptName=Lib1,Lib2` — тогда все функции библиотеки доступны скрипту
сразу, без `ImportedFunction` на каждую.

## Проверено в игре: правка сохранения работает

Взяли `CE_Eltan_FirstArm.sav`, переименовали три системы в «Эльтанская Рана»,
«Первый Приют», «Крепость Карх», записали обратно через `tools/sav_tool.py`
и загрузили из меню игры. **Движок файл принял, названия видны на карте.**

Важно: контрольная сумма галактики (`_1cc`, по заголовкам движка — CRC)
библиотекой не пересчитывается, переносится как есть. Загрузке это не
помешало — значит движок её при загрузке не проверяет, по крайней мере в
этой сборке.

### Но сайдкары непригодны как основа

При загрузке обнаружился визуальный мусор: ангарный диалог поверх звёздной
карты. Проверено на **неотредактированном** оригинале — то же самое. То есть
дело не в правке.

Причина в происхождении файлов: `CE_Eltan_FirstArm.sav` и
`CE_Eltan_SecondHome.sav` пишутся нашим кодом **посреди генерации новой
партии** (`ce_dual_newgame_execute` вызывает `SaveGame` сразу после
`Execute`), когда движок ещё не в игровом состоянии. Сейв запоминает
недостроенный интерфейс и тащит его при загрузке.

Похоже, этим же объясняются и другие наблюдавшиеся странности перехода:
камера, зависающая в космосе, и появление на стартовой станции.

**Вывод для архитектуры.** Основой Второго Дома должна быть **нормально
сохранённая партия**, а не снимок на лету: начать новую игру, дойти до
живого состояния, сохраниться штатно — и уже этот файл переписывать под
Эльтан (имена систем, планеты, станции, владельцы, корабли) и переносить в
него капитана.
